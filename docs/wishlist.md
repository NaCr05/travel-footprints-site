# 愿望清单

导航里的 Wishlist / 愿望清单与已到访记录独立。城市和选填理由公开展示，编辑沿用地图现有的 GitHub 主人登录；不扩大 GitHub App 的仓库或权限范围。

## 使用

1. 打开愿望清单，点击“添加城市”。先显示精选目的地，可按中国 / 海外切换。
2. 输入中文、英文、别名或已核对的常用拼音；结果列出国家和行政区，请选择正确的同名城市。
3. 选填理由，主人登录后保存。保存由服务确认后，当前清单和地图立即更新；公开网站通过既有 GitHub Pages 流程后台发布。
4. 点击已保存城市可修改理由，或确认移出清单。移除愿望不修改到访记录、月份或照片。

地图的“显示愿望城市”开关默认开启，并在当前浏览器记住选择。关闭只隐藏标记；即使侧栏收起也能操作。想去的地方显示 6px 外径、1px 边框的香槟色空心圆；已到访且想再去的城市共用原标记，保留蓝心并加细边。不会移动坐标、聚合成大圆、常驻文字或混入到访统计。键盘焦点/鼠标悬浮显示城市和理由，点击进入详情。

## 搜索数据

GeoNames cities5000 的本地精简目录当前包含 69,789 个地点（2026-10-11 快照）。69,789 不代表全世界所有城镇，也不表示旅游热度。41 个精选目的地人工编排，每类先展示最多 12 个；搜索最多返回 30 条，优先名称/别名精确匹配、前缀，再是较长关键词的包含匹配，人口仅辅助同名排序。

搜索和精选目的地使用同一套地名规则。英文名称优先使用 GeoNames 标记为 `en` 的名称；中文只取 `alternateNamesV2` 中明确标记为中文的名称，优先简体语言标签，并用 OpenCC `t2s` 统一字形。不从未标记语言的汉字别名猜译名，不使用历史或俗称条目作为展示名；人工核对过的精选/已到访城市名称保持优先。中文模式下确实没有中文译名的城市或地区保留原名，附上“暂无中文译名”。资料加载失败则单独提示“译名暂不可用”，可以重试。

`data/cities/locales.json` 按 GeoNames ID 存城市的 `[英文名, 中文名]`，按 `国家代码:原地区名` 存行政区名称对。清单、搜索结果、详情、地图提示和标记的无障碍名称统一经过 `site/city-labels.js`。切换语言不改变记录身份；旧清单即使保存时没有中文名，也能按 ID 补齐展示。个人理由保持原文，不自动翻译，也不改写日期、坐标或旧记录。覆盖数量与来源哈希记录在 `data/cities/index.json`。

首页只额外读取精简地名字典，不加载完整搜索目录。打开添加界面先取小型精选索引；第一次输入搜索才在独立浏览器 Worker 内加载 16 个目录文件，最多 4 个并行。目录体积由构建脚本报告（实际传输取决于服务器压缩）。所有查询在浏览器内完成，不将理由发送给 GeoNames 或第三方搜索服务。

目录按 `GeoNames ID % 16` 分片，每片小于 GitHub Contents API 的 1 MB 文件内容限制。重新生成需要 Python 3.11+；建议在仓库外建立虚拟环境，安装仅构建时使用的 OpenCC：

```sh
python -m pip install -r scripts/requirements-catalog.txt
python scripts/build-city-catalog.py /path/to/external-download-cache
```

缓存应留在仓库之外（包含较大的 `alternateNamesV2.zip`）。网站运行和普通部署不需要 Python、OpenCC 或实时地名服务。来源哈希和归属许可见 `data/cities/index.json`、`THIRD_PARTY.md`；增加人工校正或精选目的地时修改构建脚本并重新核对，不直接手改生成分片。

## 保存与发布

- `GET /api/wishlist` 在同一 Git 提交读取清单和版本。
- `POST /api/wishlist` 只接受 `base`、GeoNames `id` 和理由。地点身份与坐标从同版本固定目录读取，不信任客户端传入的路径、名称或坐标。
- `DELETE /api/wishlist` 只移除指定愿望。新增、修改、移除均只写 `data/wishlist.json`，不更改照片或城市记录。
- 每次请求校验正式地图来源、加密会话、主人 ID、仓库 ID 及现有写权限。一次提交配合非强制分支更新；版本冲突拒绝覆盖，前端保留草稿供重新读取后保存。
- 重试已完成的相同操作不会重复新增或删除。理由最多 500 个 JS 字符单位，最多 500 个愿望。
- 发布产物附带最近 64 个提交 ID；前端仅在产物包含已确认提交时提示发布完成。未发布、网络失败或后台较慢均保留已确认的当前列表。会话只放在内存，刷新需重新登录；地图显示偏好单独保存在本机。

## 服务升级

本次地名语言修复仅更新静态目录和前端，沿用原有字段及 16 个分片；不需要升级 Worker/Pages 入口或增加授权。以下是首次接入愿望清单时的服务要求。

新前端需要同步部署 `upload-service/worker.js` 和 `upload-service/pages-gateway/public/_worker.js`；后者新增 `/api/wishlist` 固定路由。只升级网页而不升级入口会返回 404。已有来源、GitHub 回调地址、服务绑定和密钥均不改变。

部署顺序：先更新向后兼容的 Worker 和 Pages 入口，再通过 PR 合入数据与程序并等待 GitHub Pages 构建通过。GitHub App 不需要新授权，Cloudflare 入口沿用原域名。

2026-10-11 接入记录：Worker 已发布为 `95b19fed`（控制台显示 Active / Latest），所有者已手动更新原 Pages 入口 `travel-footprints-upload-check`。实际 `/health` 返回 `200 {"ready":true}`；来自地图、未登录的愿望清单和照片读取均返回 401；其他来源的愿望清单请求返回 403。服务入口已就绪，网页随本次 PR 合入后发布。上述检查确认路由和访问限制生效，不代表真实所有者的愿望保存已验证。

## 验证边界

本地自动测试覆盖城市检索、地图图层语义、版本凭据、固定文件写入、未登录/错误来源/权限拒绝、并发冲突、重试和原有照片功能。隔离浏览器测试使用合成愿望与模拟 GitHub API，覆盖 6px 尺寸、隐藏不删除、刷新记忆、同名选择、空理由、冲突恢复和移除。合成测试清单不进入仓库或正式站；真实所有者登录后的生产保存仍需上线后实际使用验证。
