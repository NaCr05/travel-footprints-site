# 城市相册：Pages CMS 试接入

目前试用一座城市、两张照片。网页编辑器负责把图片与相册清单写回 GitHub，网站由现有 GitHub Actions 检查后发布，原地图网址不变。罗马 2026 年 8 月的两张照片已通过 Pages CMS 完成网页上传和仓库同步验证；本地预览已核对封面、两张照片放大和中英文月份。

## 第一次连接

1. 打开 [Pages CMS](https://app.pagescms.org/)，使用自己的 GitHub 账号登录。
2. 安装官方 GitHub App 时选择 **Only select repositories**，仅选择 `travel-footprints-site`，核对实际显示的权限后确认。
3. 在 Pages CMS 选择仓库和 `main` 分支。日常可直接打开 [相册管理页](https://app.pagescms.org/nacr05/travel-footprints-site/main/file/photo-albums)；`main` 更新才会触发正式发布。需要单独试验时可以使用其他分支，检查后再合并。
4. 打开 **City album pilot / 城市相册试用**。

`.pages.yml` 控制编辑器展示哪些字段，不是仓库访问权限的隔离机制。GitHub App 的权限作用于所选仓库；地图访问者不会因为能看公开网页而获得编辑权限。前端不保存 GitHub token。

## 添加两张照片

1. 添加一个试用相册，在 **City / 城市** 中选定已有城市。
2. **Visit month / 到访月份** 填该城市已经记录的 `YYYY-MM`，例如洛杉矶为 `2019-07`；不关联某次到访则留空。此表单不会新增到访月份。
3. 在 **Photos / 照片** 中添加两项，使用图片字段上传或拖入选好的 JPG、PNG、WebP，可填写说明。第一张为封面，图片可在列表中调整顺序。
4. 保存相册。若在试接入分支上操作，先检查变更再合并到 `main`；日常使用 `main` 时保存会直接触发发布。
5. 在仓库 **Actions** 中等本次发布成功，再刷新地图进入对应城市。确认封面、两张缩略图、点击放大以及月份正确。

图片上传和相册保存可能产生不同的 Git 提交。**上传文件就会进入公开仓库**，保存相册才把它关联到城市；即使未保存相册，也不能把已上传图片视为私密草稿。照片只选择准备公开的版本，先清除不希望公开的位置等元数据。Pages CMS 在这份配置中不负责自动压缩或清除元数据。

每张图片限制小于等于 8 MiB，建议先使用适合网页浏览的尺寸。未知城市、非已有月份、错误路径、缺失图片或超出试用数量会让检查失败；失败时原来的网站仍继续显示。管理后台能成功保存不代表网站已发布成功。

## 数据如何同步

- `data/places.geojson`：保持现有城市、坐标和到访记录。
- `data/photo-albums.json`：只保存城市 ID、可选月份、照片路径与说明。
- `photos/`：Pages CMS 上传的图片，自动使用随机文件名以减少重名覆盖。
- 本地预览和网站导出使用同一段合并逻辑，不会改写原城市数据。
- 网站使用 `./photos/...` 相对路径，兼容现有 GitHub Pages 项目网址。

Pages CMS 保存列表时会替换整个列表，保存空内容时还会移除空数组。因此不把整份城市 GeoJSON 交给照片编辑表单；独立相册清单只影响照片。清空相册后，城市详情恢复原来的小地图与空状态。

## 试用验收与回退

- 用实际选定的两张照片完成一次网页上传和相册保存。
- 核对 GitHub 中新增图片与相册清单，确认 `data/places.geojson` 没有改动。
- 发布成功后，不登录也能在原网址看到两张照片，点击可放大，中英文切换正常。
- 另选一座无照片城市，确认原有详情和到访月份不变。
- 移除相册中的照片并保存可以撤下网页展示；已经提交的图片仍可能存在于仓库和 Git 历史中。图片公开前应完成选择。

如果暂不继续使用 CMS，可以保留空相册清单，并在 GitHub 中撤销该 App 对此仓库的访问。地图本身不依赖 Pages CMS 在线运行。扩大到更多城市、自动压缩和在地图页面直接上传属于后续工作。
